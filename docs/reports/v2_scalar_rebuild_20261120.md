## 实际发现和修复

1. ClickHouse 25.8 不允许在 JOIN ON 以外使用 `isNotDistinctFrom`。验收脚本改用“空值状态不同，或两个非空值不同”的表达式；已在真实季度表对比中执行。
2. 一次读取比较全部 1,736 个旧值列触发 16 GiB 验收内存上限；已把验收 SQL 改为每批 128 列，保留逐列精确空值比较。
3. 首次历史宽表写入在 339.18 秒触发测试设置的 32 GiB 内存上限。堆栈定位于 `MergeTreeDataPartWriterWide` 的压缩流分配：上千个可空列、多年度分区及并行写入叠加。SQL 改为 `max_insert_threads=1, max_compress_block_size=65536`，计算逻辑不变，重试仍使用 32 GiB 上限。
4. 失败 INSERT 留下 4,590 行部分结果；已保留为 `v2_scalar_rebuild_20261120.dws_stock_factor_wide_v2_sample_failed_32g`，不用于验收。失败查询 ID：`7f9501e1-3948-47d5-a7b8-9e752674e6fd`。
5. 股东户数原始数据共 479,186 行，其中 3,894 行公告日早于报告期，按既定规则排除。剩余行数还受 2010 年起始边界和版本去重影响，不能把全部行数差额解释成日期异常。
6. 试建期间行情源更新到 2026-11-20；最初盘点正式 v2 截至 2026-11-19。需分别报告键集合变化和重合日期的数值对比，不把未构建的新交易日误判为字段回归。

全市场两日查询首次在客户端计时 429.09 秒（服务端 423.29 秒）、聚合结果读取阶段触发 32 GiB 上限，未留下结果行。重试对等值日频关联源裁剪至 2026-11-19～20，财报、研报、指数快照和北向历史保持完整；限制改为 4 线程、64 GiB、2 GiB 外部排序/聚合阈值。该范围裁剪不改变目标日取值口径。

## 执行与验收约束

历史样本查询限制为 8 个计算线程、32 GiB 查询内存、4 GiB 外部排序/聚合阈值、20 分钟执行上限、2 MiB SQL、500,000 AST 节点。源表使用只读视图，季度实体候选在两组宽表中复用；历史样本只按股票裁剪源表，保留全部财报和研报历史；指数快照保留全指数成分，避免个股过滤破坏快照日期。

旧值对比排除五个构建与血缘列，其他列作精确空值安全对比；独立 Python 校验从 DWD 重新选取可见报告及固定自然季度，并从累计值重算单季、TTM 和年度值。浮点重算允许 `rel_tol=1e-12, abs_tol=1e-8`，原有列一致性对比不使用该容差。

独立 PIT 核验脚本为 [independent_pit_check.py](v2_scalar_rebuild_20261120/independent_pit_check.py)，从仓库根目录以 `PYTHONPATH=. python docs/reports/v2_scalar_rebuild_20261120/independent_pit_check.py` 重跑；增加 `--latest-tax-only` 核对全市场中的非空递延税样本。脚本只读数据库并更新本地核验 JSON。源视图读取运行时数据，并未冻结为跨查询事务快照；源更新后重跑应重新审阅差异。

两个候选库及查询日志均保留供复核。未做全市场全历史 v2 重建，未交换正式表，不能从这两组试建直接推断完整历史任务的资源需求。

宽表与标量相关 17 项回归/数值测试通过；其他相关回归组重跑 98 项通过（含重复用例），Ruff 和 `git diff --check` 通过。
